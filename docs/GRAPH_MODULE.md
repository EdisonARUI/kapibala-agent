# 流程编排模块 (Graph Module) - 技术文档

## 概述

流程编排模块 (Graph Module) 是获客初筛 Agent 的主控中心。它的核心职责是：定义全局状态 (State)，串联各个独立的功能节点 (Nodes)，并配置控制流 (Edges) 以实现整个系统的自动化运转。本模块基于 LangGraph 构建。

## 2. 核心功能

### 2.1 全局状态定义 (State)
位于 `graph/state.py`，使用 `TypedDict` 定义了整个工作流共享的数据结构 `AgentState`，包含以下关键字段：
- `messages`: 历史对话列表 (支持 `operator.add` 累加)。
- `intent`: 当前识别出的客户意图。
- `is_unhappy`: 客户是否处于负面情绪状态。
- `abnormal_count`: 异常行为计数。
- `is_escalated`: 是否已转交人工。
- `message_timestamps`: 消息时间戳记录。
- `reply_content`: 生成的回复内容。

### 2.2 工作流构建 (Workflow)
位于 `graph/workflow.py`，负责将各个模块组合成有向图：
- **节点注册 (Nodes):** 将各模块的功能函数 (如 `guardian_node`, `analyzer_node`, `reply_node` 等) 注册为图的节点。
- **条件路由 (Conditional Edges):**
  - `route_after_guardian`: 拦截器判定，如果是 `silent_escalated` 则直接结束，否则流转至意图分析。
  - `route_action`: 动作路由，根据更新后的意图 (`state.get("intent")`)，分发到具体的动作节点 (回复、预约、转交或标记不感兴趣)。
- **统一出口:** 所有动作节点执行完毕后，统一流转至 `rate_limiter` 节点进行速率限制检查，最后到达 `END`。

---

## 3. 输入与输出

**输入 (工作流启动)：**
- 初始化后的 `AgentState` 对象，包含初始的消息内容和其他默认状态。

**输出 (工作流结束)：**
- 更新后的 `AgentState` 对象，状态中可能包含了新的回复内容、更新的意图、修改的标记等信息，供外部调用系统处理或存储。
