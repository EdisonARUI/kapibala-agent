# 获客初筛 Agent MVP 架构设计

为希望了解获客初筛 Agent 内部实现的开发者提供的技术文档。本架构设计基于 [requirements.md](requirements.md) 中的需求，描述了系统的核心模块拆分与整体流转方案。

---

## 概述

获客初筛 Agent 系统被拆分为 6 个高内聚、低耦合的核心模块。系统通过底层的调度引擎（如 LangGraph）将这些模块串联为一个完整的处理工作流，以确保安全性、业务可控性与系统扩展性。

## 模块文档

具体的模块实现细节、内部流转与 API 定义，请参阅各个模块对应的子文档。

| 模块 | 职责描述 | 文档 |
|------|----------|------|
| **前端 (Frontend)** | 负责用户交互界面，接收输入并展示 Agent 状态与回复。MVP 阶段可为简易 CLI 或 Web 原型。 | [FRONTEND_MODULE.md](FRONTEND_MODULE.md) |
| **防御模块 (Defense)** | 侧重于系统边界安全。负责入口处的拦截（黑名单、异常状态锁死）、出口处的敏感词过滤（防内部信息泄露）、以及速率限制。 | [DEFENSE_MODULE.md](DEFENSE_MODULE.md) |
| **意图识别模块 (Intent)** | 系统的 AI 大脑。负责构建上下文，调用大模型分析客户意图（如需要回复、转人工、不感兴趣等）及情绪。 | [INTENT_MODULE.md](INTENT_MODULE.md) |
| **解析模块 (Parsing)** | 负责将大模型非结构化的输出或 JSON 解析为系统可读的强类型数据结构，并处理由于幻觉导致的格式错误与重试机制。 | [PARSING_MODULE.md](PARSING_MODULE.md) |
| **约束模块 (Constraint)**| 侧重于核心业务逻辑控制。负责维护和校验状态机规则，例如“连续两次异常/不满则强制转人工”的业务流程干预。 | [CONSTRAINT_MODULE.md](CONSTRAINT_MODULE.md) |
| **动作执行模块 (Action)**| 根据系统最终确定的意图，安全地执行预设的白名单动作（如生成拟人化回复、标记系统状态、发送转人工通知等）。 | [ACTION_MODULE.md](ACTION_MODULE.md) |

## 后续开发计划

1. **补全模块详细文档**：为上述 6 个模块编写详细的技术规范文档。
2. **调度引擎搭建**：配置 LangGraph 环境，将 6 个模块组装为工作流图。
3. **分模块实现**：按模块依赖顺序，逐步实现各个模块的核心代码。
4. **集成测试**：编写模拟交互脚本并实测系统的边界安全和业务约束机制。
