# 获客初筛 Agent MVP 需求拆解

## 1. 核心目标
构建一个自动化获客初筛 Agent，能够接收客户消息，使用大语言模型（LLM）判断客户意图和情绪，并执行相应动作。系统需严格满足特定的业务和安全约束，我们将采用 **LangGraph** 作为 Agent 的核心编排框架。

## 2. 功能需求拆解

### 2.1 交互通道 (界面/输入)
- **需求**：实现一个简单的"模拟客户对话"通道，无需接入真实 IM。
- **拆解**：
  - 实现一个简单的终端命令行交互，或最基础的网页聊天框（如基于 Streamlit / Gradio / 原生 HTML+JS 等，重点是越简单越好）。
  - 支持用户输入文本消息，并展示 Agent 的内部判断状态、触发的动作及回复内容。

### 2.2 核心 Agent 处理逻辑 (基于 LangGraph)
- **需求**：处理客户消息，判断意图和情绪，执行对应动作。
- **拆解**：
  - **意图与情绪识别 (LLM 驱动)**：将客户消息输入 LLM。
    - **意图 (Intent)**：分类为 5 种之一（有兴趣 / 需要更多信息 / 明确拒绝 / 答非所问 / 其他）。
    - **情绪 (Sentiment)**：正交信号，独立判断客户是否**情绪明显不满**。
  - **动作路由逻辑 (LangGraph Conditional Edges)**：根据识别结果从以下动作集合中选择其一执行：
    - `reply`：生成回复草稿（调用 LLM 生成内容）。
    - `schedule_followup`：标记稍后跟进，本轮不回复。
    - `escalate_to_human`：转人工，系统进入永久静默状态，直到人工重新激活。
    - `mark_not_interested`：标记不感兴趣，结束当前会话。

### 2.3 硬性约束 (核心难点，代码层面强制)

#### 2.3.1 速率限制 (Rate Limiting)
- **需求**：对同一个客户，任意 60 秒窗口内最多只能主动发出 1 条消息。
- **拆解**：
  - **机制层拦截**：在消息最终输出节点（或拦截器中）实现滑动窗口（Sliding Window）限流，记录发送时间戳。
  - **保证**：无论 LangGraph 内部怎么反复调度重试，最终外发 `reply` 必须通过此独立逻辑卡住。

#### 2.3.2 连续异常强制转人工状态机
- **需求**：连续两次被判定为"答非所问"或"情绪不满"，必须 `escalate_to_human` 并静默。
- **拆解**：
  - **状态隔离**：在 LangGraph 的 State 中维护独立的 `abnormal_count` 和 `is_escalated` 状态，共用一个计数器（其它意图重置为0）。
  - **确定性流转**：状态更新和路由由纯代码的确定性状态机完成，不依赖 LLM 决定，一旦满足两次立即截断后续流程进入静默。

#### 2.3.3 防越权执行 (Prompt Injection Defense)
- **需求**：对话内容不能反向指挥 Agent 执行 4 个动作之外的行为，不能绕过转人工后的静默。代码层面 100% 强制。
- **拆解**：
  - **入口强阻断**：在图的起始节点前置检查 `is_escalated`，若为 True 则直接返回，不触发后续大模型调用，断绝绕过静默的可能。
  - **动作白名单硬编码**：Agent 只能输出 Enum 类型（4种预设动作）。执行动作通过代码映射（如 `match/case`），即便大模型幻觉输出了未授权指令，代码层面也会在路由或执行时抛出异常或默认 fallback。

#### 2.3.4 防内部信息泄露 (Data Exfiltration Defense)
- **需求**：防止客户套出 prompt、规则、价格等内部信息。
- **拆解**：
  - **Prompt 指令强化**：在 System Prompt 建立核心准则，拒答一切涉及设定的问题。
  - **双重防线 (Output Guardrail)**：如果 `reply` 的内容生成完毕，可引入额外的规则检查或小模型 Guardrail 审核，确保输出内容中不包含系统设定的敏感词、提示词片段，讲清此层防御的边界（即不可能 100% 拦住隐晦的语义泄露）。

## 3. 交付物清单
- **可运行 Demo**：最小化可跑通的代码库，附带启动和测试说明。
- **架构与约束说明**：在 README 中清晰阐明每条硬约束（尤其是速率限制、状态机、防越权）在代码的**哪一层**被强制保障，以及防套话设计的**防御边界**。
- **针对性测试用例**：提供至少 3 条特定的"越界/刁难"对话用例及测试运行结果，演示系统在受攻击时的真实反应。

## 4. LangGraph 架构设计草案 (供后续开发参考)
- **State (状态图定义)**:
  - `messages`: 会话历史记录
  - `intent`: LLM 判定的意图
  - `is_unhappy`: 是否情绪不满 (Boolean)
  - `abnormal_count`: 连续异常计数器 (Integer)
  - `is_escalated`: 是否已转人工 (Boolean)
  - `message_timestamps`: 记录最近发送消息的时间戳列表 (用于滑动窗口测速)
- **Nodes (节点划分)**:
  - `guardian_node`: 入口拦截检查（检查静默状态等）。
  - `analyzer_node`: 调用 LLM，格式化输出意图和情绪。
  - `state_updater_node`: 纯代码处理异常计数逻辑。
  - `action_executer_node`: 根据判定执行对应方法。
  - `rate_limit_checker`: 执行发信前的 60 秒限速核查。
- **Edges (控制流)**: 基于状态中更新的指标做条件路由 (Conditional Edges)。
