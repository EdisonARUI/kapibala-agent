# 动作执行模块 (Action Module) - 技术文档

## 概述

动作执行模块 (Action Module) 是工作流的最后一公里。它接收经过意图识别、解析验证以及业务约束层层过滤后的“终态意图”，执行预设的白名单动作（如回复用户、触发业务流、打标签）。

## 2. 核心功能

### 2.1 意图路由分发
- 作为一个纯代码级的 `match...case` 语句，只允许执行白名单内的动作操作。拒绝任何未知动作。

### 2.2 拟人化回复生成 (Reply Action)
- 仅当 `intent == 'reply'` 时，才第二次调用 LLM（或基于模板），专门为了生成拟人化的话术草稿。
- 这一步的大模型 Prompt 与“意图识别”截然不同：这里扮演销售客服，态度友好，遵循销冠的应答技巧。

### 2.3 业务动作执行 (Background Actions)
- `escalate_to_human`：生成一条友好的转接提示（如“请稍候，马上为您安排专人”），并通过 Webhook/API 通知真人客服系统。
- `mark_not_interested`：将该线索在 CRM 数据库中打上“沉寂/放弃”标签，不产生任何外发消息。
- `schedule_followup`：更新线索跟进时间。

---

## 3. 与其他模块的关系

动作执行模块生成的 `reply` 消息，在最终发送给前端之前，**必须**流入防御模块的出口守卫（Output Guardrail 与 Rate Limiter），确保生成的内容不违规且发送频率不超标。
