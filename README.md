# Kapibala Agent (获客初筛)

本项目是针对“kGroup 实习生笔试题 - Agent 方向”实现的一个获客初筛 Agent。通过分析客户的对话内容来判断其意图和情绪，并在安全的边界内自动执行相应的动作。

## ⏱️ 开发耗时与取舍

- **实际耗时**：约 13H。
- **功能取舍**：为了在有限的时间内保证硬性约束（速率限制、防越权、防套话等）在代码层面绝对生效，MVP 阶段简化了前端交互界面（仅提供简易 CLI/Web 通道），同时没有接入真实的 IM 平台，重点打磨底层的多模块编排与状态流转机制。

## 🚀 启动与使用指南

1. **环境安装**：
   确保 Python 3.10+ 环境，然后安装依赖：
   ```bash
   pip install -r requirements.txt
   ```
2. **配置环境变量**：
   在项目根目录创建 `.env` 文件，并填入提供的 GEMINI_API_KEY：
   ```env
   GEMINI_API_KEY=your_api_key_here
   ```
3. **运行 CLI 与 Agent 对话**：
   ```bash
   python main.py
   ```
4. **运行前端与 Agent 对话**：
   ```bash
   python web/web_app.py
   ```

## 🏗️ 架构设计与框架选择

### 为什么选择该架构？
本项目基于 **LangGraph** 构建。选择该方案的核心原因在于：纯 Prompt 控制或传统的单链（Chain）结构无法满足严格的“硬性约束”。我们需要一个**状态机（State Machine）驱动的工作流**。

通过将系统拆分为 `前端`、`防御 (Defense)`、`意图识别 (Intent)`、`解析 (Parsing)`、`约束 (Constraint)`、`动作执行 (Action)` 和 `流程编排 (Graph)` 七个模块（详情参见 [ARCHITECTURE.md](docs/architecture.md)），我们可以确保每一步操作都受到严格的代码级管控，而不是依赖 LLM 自身的自觉性。

### 🛡️ 硬性约束的代码层强制机制

1. **速率限制的双重防御（60秒内最多1条主动消息）**：
   - **实现层**：在 `防御模块 (Defense)` 的入口 (`guardian_node`) 与出口 (`rate_limit_checker`) 进行双重拦截。
   - **机制**：通过维护一个60秒内的 `message_timestamps` 列表，如果发现在任意60秒内发送消息数量达到或超过限制，系统会在**入口处直接拦截**，将意图设置为 `rate_limited` 并直接路由结束，完全跳过大模型调用。出口处再次进行双重保险校验，拦截超限动作并阻止原有消息发出。

2. **连续两次“答非所问”或“情绪不满”强制转人工与静默**：
   - **实现层**：在 `约束模块 (Constraint)` 的状态机更新和 `Graph` 路由中实现。
   - **机制**：维护一个 `abnormal_count` 计数器，独立于大模型意图输出。一旦该计数器 `>= 2`，状态更新器会强制覆盖 LLM 的意图为 `escalate_to_human`，并将状态标记为 `is_escalated=True`。
   - **静默机制**：触发转人工后，后续对话在入口 `guardian_node` 被识别，直接设定为 `silent_escalated` 意图，Graph 路由直接短路至 `END`，严格保持静默，绝不消耗 LLM 资源。

3. **防越权执行动作与安全路由**：
   - **实现层**：在 `动作执行 (Action)` 与 `Graph` 流程编排处。
   - **机制**：代码层面 100% 强制约束。所有的动作执行（如 `reply_node`, `escalate_to_human_node` 等）作为独立的节点在 Graph 中注册，并通过条件边（Conditional Edges）严格路由。大模型解析的输出仅作为路由的判断依据（意图分类），真正的动作执行逻辑硬编码在具体节点中，彻底杜绝了模型输出越权指令的可能。

4. **防套话与结构化输出（系统提示词/内部规则保护）**：
   - **实现层**：在 `意图识别模块 (Analyzer)` 和 `执行模块 (Executor)` 的大模型交互边界。
   - **防线设计**：
     - **强类型约束**：使用 `pydantic` 定义输出结构（如 `IntentOutput`, `ExecutorOutput`），并通过 `with_structured_output` 强制要求模型严格按照设定格式返回，大幅度降低了被注入诱导输出自由文本的风险。
     - **CoT 物理隔离**：模型的思考推理过程（Reasoning）单独提取记录日志，不向用户端暴露。用户端仅能收到经过最终处理的 `reply` 内容，有效防止通过套话获取系统内部判断逻辑。
